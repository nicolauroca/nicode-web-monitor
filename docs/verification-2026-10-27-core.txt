Reproducing the native experiment (developers, disposable sites only)
1. Install Joomla 6.1.3 using its official installer in an isolated database/root.
   Disable mail and all scheduler/cron/web writers. Set the site offline. Obtain
   the official 6.1.4 Update_Package and independently verify its SHA-256.
2. Preserve a complete file baseline outside the web root. Create a private empty
   snapshot directory outside it. Deliberately create .nwm-disposable-core in the
   disposable root to acknowledge the test-only destination.
3. Run with that site's PHP CLI, replacing paths and digest:
   php tests/core_update_native.php JOOMLA_ROOT UPDATE_ZIP SHA256 PRIVATE_SNAPSHOT_DIR --allow-disposable-writes
   The test captures its database, writes core-started.json before update effects,
   uses the native Joomla model and retains native-returned.json. No production
   execution permission is implied. Do not rerun an interrupted attempt or reuse
   its directory; inspect existing effects first.
4. In a NEW PHP process run tools/core_update_preflight.php against the updated site
   and the same package. Expected blocker is only target_not_newer, with all three
   versions 6.1.4 and schema_errors=0. Check frontend/admin login separately.
5. Restore the captured database with DatabaseSnapshot into a DIFFERENT empty
   database, copy the saved file baseline to a separate root, and compare schemas,
   row multisets and file hashes before changing clone connection/path settings.
   Verify every configuration write. Boot the recovered site and verify 6.1.3.
   See the existing backup/recovery documentation for provider limits. A snapshot
   or successful installer return alone does not demonstrate recovery.

Remaining product gates
Native core provider with durable operation IDs, completion in a fresh process,
remote HTTPS integration, central permissions/confirmation and reconciliation
following lost responses remain pending. The test reservation is an experimental
local guard, not that product journal. Rollback was manual to a separate clone,
not automatic recovery. Other extension types/catalog downloads, backup runner
usability, compatibility beyond this environment and clean-source release QA remain
open. No release or full-product readiness is claimed by these checks.
