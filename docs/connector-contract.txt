Nicode Web Monitor read-only connector protocol 1 / development 0.2.0

Route: GET /index.php?option=com_nicodewebmonitor&task=inventory
System plugin handles only the frontend onAfterInitialise event; it terminates
before page rendering. It does not handle administrator or API applications.
The standalone system ZIP bundles a namespaced copy of the existing collector;
the console plugin is not a dependency. Build output has deterministic metadata.

Authentication: Authorization: Bearer <64 hex characters from 32 random bytes>.
SHA-256 of the exact encoded credential is stored in Joomla plugin parameters.
Comparison uses hash_equals. Each installation requires a unique UUID v4.
Empty/invalid digest or invalid UUID closes the connector. Replacing the digest
rotates the credential immediately. Disabling the plugin removes the endpoint.
No tokens in query parameters, cookies or POST bodies. No users or passwords in
inventory. Authentication must precede collection. One read-only scope exists;
no update or backup command is implemented or implied by this credential.

HTTPS must be established by the trusted PHP server environment. Forwarded and
X-Forwarded-Proto are ignored. Production web-server/proxy deployment and rate
limiting remain to be validated. Protect Authorization from access/error logs.
A bearer credential can be reused until revoked: this is not request signing.

Response 200: protocol_version=1, site_id and inventory (existing schema 1).
inventory.execution_context=remote_https; remote_inventory=true; remote_updates
and remote_backups=false. Partial collection remains explicit inside inventory.
200 is not an assertion that the monitored site is healthy or fully inventoried.
Runtime reports web PHP, which may differ from local CLI. No persistence is added.

403 https_required; 503 connector_unavailable (configuration/revocation);
401 unauthorized; 405 method_not_allowed (Allow: GET); 404 operation_not_found;
503 collection_failed for exceptions escaping the collector. Errors omit internal
exception text and site identity. Responses are JSON with no-store/private.

Client contract for the upcoming central component: validate HTTPS certificate,
reject redirects, use bounded timeouts/body size, check protocol and enrolled
site UUID before storing data. Authentication failure is not a healthy/empty
inventory. Preserve last successful observation with its age and latest error.
Central HTTPS requests are implemented in InventoryClient (2026-10-06).
Client-side storage and UI are not implemented yet.
