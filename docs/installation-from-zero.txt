Nicode Web Monitor 1.1.1-dev.3 — instalación y conexión

Requisitos
Joomla 6, PHP y base de datos compatibles con esa instalación. PHP necesita cURL,
Sodium y las extensiones nativas de Joomla. Ambos sitios deben servir HTTPS con
certificados válidos y ser accesibles mediante nombres de dominio públicos.
El servidor debe transmitir Authorization a PHP y establecer HTTPS de forma fiable.
Las cabeceras Forwarded y X-Forwarded-Proto no habilitan confianza automáticamente.
El requisito de destino público se aplica a los sitios remotos. Para monitorizar
este mismo Joomla, el inventario se obtiene localmente y no necesita acceso a su
propia dirección pública ni resolver DNS.
Python 3 se utiliza solo al reconstruir los paquetes desde el repositorio.

1. Obtener los instaladores
Desde la raíz del repositorio: python tools/build.py
Los dos archivos para usuarios son:
 - dist/pkg_nicodemonitor-1.1.1-dev.3.zip: panel central y plugin de tareas.
 - dist/pkg_nicodeconnector-1.1.1-dev.3.zip: componente de conexión y motor system.
El build también genera ZIP individuales para pruebas y un plugin CLI opcional;
no instalarlos en el recorrido normal. Descargar los dos pkg_ de la prerelease
1.1.1-dev.3, no «Source code» ni los ZIP de una release anterior.

2. Instalar
En el Joomla central, Sistema > Instalar > Extensiones: subir el paquete central.
En cada Joomla supervisado: subir el paquete Connector mediante el mismo instalador.
Abrir los componentes desde el menú Componentes. No hay que buscar, habilitar ni
rellenar parámetros de plugins para conectar el inventario.

3. Vincular
En Componentes > Nicode Web Monitor del central, en Añadir sitio, escribir un nombre
y pulsar Generar código de vinculación. Como administrador, esta acción también
prepara la tarea de comprobaciones si aún no existe. El código caduca a los diez
minutos y generar otro invalida el anterior de ese administrador.
En Componentes > Nicode Web Monitor — Conector del supervisado, introducir la dirección HTTPS
mostrada por el central y pegar el código. Pulsar Conectar.
La dirección e identidad del supervisado, las credenciales y la resolución de IP
son automáticas. El central verifica el primer inventario antes de guardar el alta.
Inventario parcial sigue siendo parcial: consultar los detalles del panel.
Las copias y actualizaciones no se habilitan con la vinculación.

Si no llega la respuesta, repetir exactamente el mismo código y dirección antes
de su caducidad permite recuperar el recibo sin dar de alta otro sitio. Para usar
un código nuevo, cancelar primero el intento pendiente en el conector. Cancelar
revoca su acceso de inventario, incluso si el central llegó a guardar el alta.
El código es un secreto temporal: no enviarlo en URLs, capturas públicas ni Git.

4. Monitorizar el propio central
Instalar TAMBIÉN el paquete Connector en ese Joomla y usar un código del mismo
panel con la dirección de ese central. Las dos extensiones tienen identidades,
menús y propietarios de paquete distintos. También es posible que un central
sea supervisado por otro central. No hay exclusión entre ambas funciones.
Si la dirección del central coincide exactamente con la dirección canónica de
este Joomla y el componente Central está instalado, la vinculación y las consultas
manuales/automáticas usan inventario local. No hay peticiones HTTP al propio sitio.
La credencial, identidad, caducidad del código y revocación siguen comprobándose.
La administración sigue requiriendo HTTPS. Los sitios remotos conservan su política
de destinos públicos y TLS; un formulario remoto no puede elegir el modo local.

5. Verificar la ejecución automática
La sección Comprobaciones automáticas distingue tarea preparada, primera ejecución
pendiente, pausa, retrasos, fallos y ejecución reciente comprobada. Seguir
automatic-monitoring.txt para el cron central. No hace falta cron en cada conector.
Una conexión correcta o una consulta manual no prueban que exista ejecución periódica.

6. Desconectar o retirar
En Nicode Web Monitor — Conector, marcar la revocación y pulsar Desconectar. El central perderá
el acceso de inventario en su próxima petición. Eliminar el registro del panel es
una acción distinta; no revoca por sí misma un secreto que conserva el conector.
Desinstalar cada paquete desde Joomla, sin desinstalar sus piezas por separado.
Retirar Connector no elimina el componente central ni sus tareas; retirar Central
pausa las tareas Nicode, invalida códigos y no desinstala Connector.
Las tablas y los directorios privados de mantenimiento se conservan. La revocación
de inventario no revoca credenciales de mantenimiento configuradas por separado.

Desarrollo sin compatibilidad anterior
Se recomienda una instalación de ensayo limpia. No se promete migración del alta
manual de anteriores versiones, ni conversión de tareas o credenciales existentes.
Reinstalar un paquete actual no es una limpieza de las tablas conservadas. Antes
de reutilizar un laboratorio viejo, decidir explícitamente qué datos conservar.

Si Central muestra 1054 Unknown column connection_type
Instalar los dos ZIP completos de 1.1.1-dev.3 encima de los existentes, sin
desinstalar, borrar tablas ni ejecutar SQL manualmente. El instalador Central
comprueba las columnas reales y añade connection_type si falta, conservando sitios,
credenciales e historial, incluso si Joomla ya marcaba el esquema como actualizado.
Después volver a abrir Central. Si había una vinculación pendiente, se puede
cancelar y generar otro código una vez que el panel vuelva a estar disponible.

Si aparece NWM: package_incomplete o la ruta de vinculación pide bearer (HTTP 401)
Instalar los dos paquetes completos de ESTA prerelease en el Joomla que tenga ambos
roles. No basta actualizar solo el componente dejando el motor system antiguo.
Cancelar cualquier intento pendiente en Conector, generar un código nuevo en
Central y conectar de nuevo. No deshabilitar TLS ni introducir secretos a mano.
Los errores ahora distinguen versiones mezcladas, autenticación inesperada,
firewall HTTP 403, ruta ausente HTTP 404, respuesta HTML/JSON y errores de servidor.
