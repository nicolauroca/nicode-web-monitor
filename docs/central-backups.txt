Central sequenced backups (0.8.0-dev, 29 October 2026)

The component now contains BackupClient and BackupCoordinator. These are backend
services connected to the administrator panel through POST-only CSRF-protected forms.
Only the joint files_and_database route is supported by this client.

An authenticated, unblocked Joomla user needs core.manage AND nwm.backup.
Enrolling/rotating the separate backup credential also needs core.admin.
The inventory credential cannot be reused. Ciphertext is bound to site UUID plus
the backup purpose, and is never included in operation receipts.

begin(site, true) creates a local random operation identity and makes no network
request. run(operation, true, true) advances exactly one sequence. run(operation)
only queries remote status. The form layer enforces CSRF and explicit confirmation for begin/advance, and uses
a redirect after each action. Status queries are also POST/CSRF protected. There is
no retry. The optional browser runner advances up to 100 sequential steps after a
deliberate confirmation, then pauses. Each HTTP request still advances one step.
It passes the observed sequence, which is compared under the operation lock before
dispatch; a second tab with an older sequence cannot advance the operation.

Each remote write is preceded by a committed uncertain journal entry. The service
requires autocommit and rejects an enclosing transaction. MariaDB named locks
serialize each operation. A transport failure leaves uncertainty and prevents
another advance. An explicit status read reconciles the same operation identity;
an unknown remote operation is not permission to restart or create another copy.
Receipts cannot regress the sequence or reopen a completed operation. This is a
current operation journal, not yet an append-only audit/history interface.

HTTPS verifies certificate and hostname, pins the enrolled IP, disables redirects
and proxies, bounds time/body/headers and never retries. Private IP exceptions and
CA overrides are constructor-only test dependencies. No form may control them.
Responses must match site, operation, scope, sequence and receipt structure; remote
bodies, paths and arbitrary extra fields are not propagated. Capture completion
does not assert restoration. A backup API response is not an approval for updates.

Installation/upgrade from the previous lab component to 0.6.0-dev was tested with
Joomla's native CLI. The schema creates separate credential/operation tables.
Site deletion removes these records with the existing registry transaction.
Schema/runtime validation currently covers the existing Windows/Joomla/MariaDB
lab; MySQL and other platforms remain acceptance gates.

Administrator workflow
Open Remote backups, expand the enrolled site and save its separate backup token
(requires core.admin plus nwm.backup). Create an operation with confirmation, then
use its own Advance backup step action after stopping all writers. An uncertain
operation has only Query backup status available. Errors never echo a submitted
token, raw exception or receipt. The latest 100 operations show state, sequence,
site and UTC update time; completion is not proof of restoration. A site removal
also removes its local backup credential and journal, not remote artifacts.

With JavaScript available, the same operation also offers Run backup steps:
1. Keep every remote writer stopped and the local maintenance permit valid.
2. Confirm the 100-step batch and click Run backup steps. Keep this tab open.
   The panel shows the next sequence; it does not invent a completion percentage.
3. Pause after current step finishes the current request and sends no next one.
   Resume requires another confirmation and continues the same operation.
4. A network error, expired login, invalid receipt or uncertain result stops the
   run. Query backup status explicitly to reconcile before continuing; do not
   create another operation as a retry. Closing the tab also stops future requests,
   but an already sent request may finish. Reload and query the same operation.
5. A complete capture disables further advancement. Restoration remains separate.

The runner is a foreground browser convenience, not a background schedule. It does
not renew the connector's local maintenance permit, stop external writers, restore
files, or approve updates. Without JavaScript the existing single-step forms work.
The JSON continuation endpoint requires the same authenticated permission, POST,
CSRF and confirmation, plus an exact expected sequence. It returns only operation,
status and next sequence on success; failures contain no raw receipt or secrets.
